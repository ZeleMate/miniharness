# Setup checklist — miniharness

Generated by the repo template for a **public** repo on GitHub **Free**.

## Automated

`./scripts/bootstrap-github.sh` (run with `--dry-run` first) does:

- [ ] Initial commit; create `ZeleMate/miniharness` and push
- [ ] Squash-only merges, PR title as commit message, auto-delete branches
- [ ] Read-only default `GITHUB_TOKEN`; Actions must be pinned to full SHAs
- [ ] Dependabot alerts and security updates
- [ ] Secret scanning + push protection, private vulnerability reporting, CodeQL default setup, approval before fork PR workflows run for every outside contributor
- [ ] Ruleset `main`: PR required, `ci-ok` required, review threads resolved, no force-push/delete, linear history

## Manual steps

1. **Account security (once per account):** passkey or security key on GitHub.
1. **Hooks:** `uvx pre-commit install` (or `prek install`).
1. **Dependabot malware alerts:** Settings → Advanced Security → enable "Malware alerts" (UI only).
1. **SonarQube Cloud:** install the SonarQube Cloud GitHub App and import the repo in organization `zelemate`. Leave **Automatic Analysis** on: it needs no CI job and no CI secret. It reports no test coverage; CI's diff-cover gate covers that.
1. **Secrets and tokens** (store, use and rotation for each are in `docs/secrets.md`):
   - **Claude review** (`CLAUDE_CODE_OAUTH_TOKEN`): run `claude setup-token` and copy the token. No Claude GitHub App is needed: the workflow posts with its own `GITHUB_TOKEN`. The token often wraps onto two lines, and a copied line break breaks it (the review then fails at once with `is_error`), so check the length (about 108) and store it without whitespace: `pbpaste | tr -d '[:space:]' | wc -c`, then `pbpaste | tr -d '[:space:]' | gh secret set CLAUDE_CODE_OAUTH_TOKEN`. Copy something else afterwards to clear the clipboard.
   - **SonarQube MCP server (local agents)** (`SONARQUBE_TOKEN`): `.mcp.json` points Claude Code at SonarQube Cloud's hosted endpoint in read-only mode, so nothing runs locally. Create a **user** token (My Account → Security; project and organization tokens don't work) and export it as `SONARQUBE_TOKEN` in the shell that starts Claude Code. On macOS, run `security add-generic-password -a "$USER" -s SONARQUBE_TOKEN -w` once, then put `export SONARQUBE_TOKEN="$(security find-generic-password -a "$USER" -s SONARQUBE_TOKEN -w)"` in your shell profile. Never put the value in a tracked file. Approve the `sonarqube` server when Claude Code asks, then check in `/mcp` that its tools don't include `change_sonar_issue_status` or `change_security_hotspot_status`; if they do, read-only mode isn't applied and only the deny rules in `.claude/settings.json` protect you. If the org is in the US region, the URL is `https://api.sonarqube.us/mcp`.
   - **Release PRs (required)** (`RELEASE_PLEASE_TOKEN`): create a fine-grained PAT (this repo; contents + pull requests read/write) and `gh secret set RELEASE_PLEASE_TOKEN`. Until it exists, `release.yml` fails on every push to `main`: the bootstrap stops Actions from opening PRs with the default token, and PRs that token opens wouldn't trigger CI anyway. Give it an expiry and rotate it. If this repo won't release, skip the token and run `gh workflow disable release.yml` instead.
   - **Template updates** (`TEMPLATE_READ_TOKEN`): if the template repo (`_src_path` in `.copier-answers.yml`) is private, create a fine-grained PAT with contents:read on that repo only and `gh secret set TEMPLATE_READ_TOKEN`. Without it the weekly "Template update check" workflow fails. Give it an expiry and rotate it.
1. **Optional:** register at bestpractices.dev for the OpenSSF Best Practices Badge (passing level is reachable).
